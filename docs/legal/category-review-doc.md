# 小程序类目与审核材料核验说明

> 产品名称：营养健康 AI 小助手
> 申报主体：成都市疾病预防控制中心
> 文档版本：v1.1（2026-09-16）
> 状态：**提交前核验材料，不得在资质未确认时直接照抄提交**

## 一、当前产品功能

正式包当前包含：

1. 健康评估及历史记录；
2. 饮食、运动、饮水打卡与正向反馈；
3. 由运营者提供的营养与食品安全科普文章，以及评论、回复、点赞、收藏、举报和互动消息；
4. 患者预约后匹配医生，进行文字或图片在线沟通；
5. AI 健康科普问答、问卷分析、每日建议和食物图片营养估算；
6. 头像、昵称、健康档案和账号注销。

普通用户不能上传或发布科普文章素材。科普文章由成都市疾病预防控制中心或其授权人员提供和维护。

## 二、类目判断必须以实际功能为准

当前版本存在真人医生匹配和一对一沟通，因此不能再用「完全不提供任何形式的医疗服务」「仅选择营养咨询且只需营业执照」作为审核说明。免责声明不能替代平台要求的服务类目和资质。

提交审核前必须由小程序管理员在微信公众平台「设置—基本设置—服务类目」查看当期规则，并根据实际上线功能二选一：

### 方案 A：保留医生在线指导

- 选择能覆盖健康咨询/问诊实际场景的医疗类目；
- 核实申报主体与实际接诊机构、医生身份和执业范围；
- 按微信公众平台当期要求提交完整资质。

腾讯云引用微信类目要求的公开说明显示，「医疗—公立医疗机构」适用于公立医疗机构提供就医、健康咨询/问诊、医疗保健信息等服务，通常要求同时提供《医疗机构执业许可证》和《事业单位法人证书》；在线看诊、疾病咨询等互联网医院场景另有互联网诊疗相关资质要求。最终以微信公众平台后台显示的最新要求及审核结论为准。

### 方案 B：无法提供相应医疗资质

- 在提审版本中关闭医生预约、医生匹配、患者与医生聊天及相应宣传；
- 重新按剩余的公益科普、健康管理和 AI 科普功能选择与实际内容一致的类目；
- 不得仅改文案而保留可访问的医生服务入口或接口。

## 三、服务边界和页面提示

无论选择何种类目，以下边界必须保持一致：

- AI、问卷和食物识别不作疾病诊断、处方或治疗承诺；
- 医生在线指导不能用于急症，回复时间取决于排队和在线状态；
- 紧急情况提示用户拨打 120 或前往正规医疗机构；
- 报告和建议标注为科普参考，食物重量和营养素为估算值；
- 页面统一使用用户确认的声明：**本应用由成都市疾病预防控制中心提供，仅供营养与食品安全科普使用，不作为诊疗依据。**

## 四、内容来源与发布权限

1. 科普文章由疾控中心或其授权人员在管理员端维护，患者端没有文章素材上传或发布入口。
2. 上线前应逐篇核对文章来源、更新时间、图片授权和审核人，不在材料中虚构固定复核周期或专家资质。
3. 用户评论、昵称、头像和咨询图片通过微信内容安全接口检测；评论保留举报、隐藏和删除机制。
4. 医生头像、姓名、职称、简介及在线状态应由运营单位核实后发布。

## 五、隐私与敏感个人信息

健康档案、健康评估、打卡及咨询内容可能属于医疗健康敏感个人信息。提审前应完成：

- [ ] 微信公众平台《小程序用户隐私保护指引》中的信息类型、用途和第三方服务，与 `docs/legal/privacy-policy.md` 及真实代码一致；
- [ ] 相机、相册、头像、手机号等隐私接口均已在微信后台如实声明；
- [ ] 对敏感个人信息的必要性、影响及拒绝后果作单独提示，并按法律法规要求取得单独同意；
- [ ] 隐私政策、用户条款、账号注销入口在未登录和已登录状态下均可访问；
- [ ] 正式环境的云托管、数据库、文件存储和 AI 服务提供方已按真实配置披露；
- [ ] 注销账号全链路已经过真机验证。

不得继续使用「绝不共享」「所有服务商均已签署 DPA」「定期渗透测试」「固定时限内删除或通知」等未经事实和材料验证的承诺。

## 七、审核问答参考

### Q1：本小程序是否提供医生在线服务？

A：按提审版本如实回答。当前开发版本包含预约匹配医生和文字、图片沟通，不能回答「完全不提供」。如最终提审版关闭该模块，应确认页面、宣传和接口均不可访问后再说明。

### Q2：AI 是否作诊断？

A：AI 用于一般健康科普、问卷内容归纳、习惯建议和食物营养估算，不生成诊断、处方或治疗结论；结果显著提示仅供参考。

### Q3：患者能否上传科普素材？

A：不能。患者只能在具体功能中提交个人头像、食物识别照片、咨询图片和评论；科普文章素材由疾控中心或其授权人员提供。

### Q4：如何处理个人信息？

A：按正式发布的《隐私政策》和微信后台《小程序用户隐私保护指引》回答，不增加尚未落地的认证、加密、审计、备份或响应时限承诺。
