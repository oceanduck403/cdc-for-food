# 微信小程序正式上线清单

> 适用于「营养与食品安全 AI 小助手」正式部署、提审和发布。平台类目、资质、备案和隐私要求会调整，最终以小程序主体在微信公众平台控制台看到的最新要求和审核意见为准。

## 一、当前上线方案

正式环境采用微信生态内的 CloudBase 云托管，不要求 Railway：

| 部分 | 正式方案 |
| --- | --- |
| 小程序前端 | 微信开发者工具上传，微信公众平台体验、审核、发布 |
| FastAPI 后端 | CloudBase 云托管运行仓库根目录 `Dockerfile` |
| 数据库 | PostgreSQL；使用 CloudBase PG 模式或同地域腾讯云 PostgreSQL |
| AI | 阿里云百炼 Qwen，由后端代理调用，Key 不进入小程序包 |
| AI 限额 | PostgreSQL `ai_usage_events` 表，当前无需 Redis |
| 用户图片 | 私有 CloudBase PG 云存储或腾讯云 COS，经后端短期签名代理访问 |
| 后端访问 | `wx.cloud.callContainer` 私有链路 |

微信公众平台只接收和发布小程序前端代码包，不能直接运行 FastAPI 和关系型数据库。FastAPI 放在微信云托管，仍属于微信 / 腾讯云的一体化部署路径。

当前已创建 CloudBase PG 环境 `cdc-food-prod-d8gtxkdw22781847c`，云托管服务名为 `cdc-food-api`。详细操作见 [微信云托管上线手册](./deploy-wechat-cloudrun.md)。

## 二、账号和控制台

- [ ] 微信小程序账号已完成适合其实际主体类型的注册与认证
- [ ] AppID 已写入项目配置，AppSecret 只保存在服务端环境变量
- [ ] 腾讯云 / CloudBase 账号由有权代表小程序主体的管理员操作
- [ ] 已开通或关联 CloudBase 环境，并记录真实 `envId`
- [ ] 已创建云托管服务，并记录创建后不能修改的真实 `serviceName`
- [ ] 阿里云百炼已开通；泄漏过的 Key 已撤销并生成新 Key
- [ ] 已为云资源设置费用预警、调用额度和管理员权限边界

不要把账号费用、审核天数或免费额度写成固定承诺。创建资源前以各控制台当日展示的价格、赠送额度和审核提示为准。

## 三、服务类目和医疗资质

服务类目必须同时匹配**小程序主体、实际页面、实际服务流程和宣传文案**。不能只靠免责声明把在线问诊功能归为普通科普。

当前产品包含医生账号、预约 / 匹配医生、在线沟通等功能。此类功能可能被平台按健康咨询、问诊、就医服务或互联网诊疗相关场景审核，所需材料不能预先简化为“营业执照即可”。应在提交前由主体管理员打开“设置 → 基本设置 → 服务类目”，按当前可选类目逐项核对适用范围和资质清单，并与主体已有证照、疾控中心授权及合作医疗机构材料保持一致。

按实际资质选择一种发布边界：

### 具备对应医疗服务资质

- [ ] 选择能覆盖真人在线咨询 / 问诊 / 预约功能的实际类目
- [ ] 上传控制台当前要求的主体证照、医疗机构证照、授权或合作文件
- [ ] 医生身份、执业信息、服务机构和可提供的服务范围可核验
- [ ] 咨询流程、用户告知、记录留存和应急转诊规则经业务及合规负责人确认

### 仅提供营养与食品安全科普

- [ ] 关闭或移除会被理解为真人诊疗的预约、自动匹配医生、问诊和诊断式表达
- [ ] AI 输出只做一般健康科普，不给出诊断、处方或治疗承诺
- [ ] 页面清楚展示“仅供营养与食品安全科普使用，不作为诊疗依据”
- [ ] 内容来源、审核人和更新日期可追溯

如果现有主体和证照不能覆盖真人在线指导，先走科普版提审；取得并核验相应资质后，再以新版本恢复相关功能。最终判断以微信公众平台和主管部门反馈为准。

## 四、CloudBase 资源

### PostgreSQL

- [ ] 生产库使用 PostgreSQL，未使用容器内 SQLite
- [ ] 若使用 CloudBase PG 模式，从腾讯云 CloudBase 控制台新建 PG 环境；微信云开发控制台目前不能创建 PG 模式环境
- [ ] 若使用腾讯云 PostgreSQL，云托管与数据库位于可互通的同地域 VPC / 子网
- [ ] 使用独立业务账号和最小权限，连接信息只存在服务端环境变量
- [ ] 已启用备份、恢复演练和必要的监控告警
- [ ] 首次发布用单实例执行 Alembic，确认迁移到最新 revision 后再扩容

### Redis

当前代码把 AI 次数和突发频率记录在 PostgreSQL，生产部署不需要 Redis。不要为沿用旧方案而额外购买 Redis。未来确需缓存或分布式锁时，再创建同地域托管 Redis，并通过 VPC 内网接入。

### 文件存储

- [ ] 用户头像和咨询图片使用私有 CloudBase PG 云存储或腾讯云 COS，并已按媒体前缀配置最小权限
- [ ] 文件不依赖云托管容器本地目录，实例重启或扩容后仍可访问
- [ ] 上传限制文件大小、图片格式和像素，并清除不需要的元数据
- [ ] 下载使用鉴权或短期签名地址，不开放匿名目录浏览
- [ ] 科普文章和运营素材只能由疾控中心授权的管理端发布，患者没有素材发布入口

## 五、云托管服务配置

- [ ] 构建上下文为仓库根目录，Dockerfile 为 `Dockerfile`
- [ ] 控制台服务端口为 `8000`，应用监听 `0.0.0.0` 和平台注入的 `PORT`
- [ ] 环境变量已从 `deploy/cloudbase/environment.example.json` 复制并替换全部占位符
- [ ] `APP_ENV=production`
- [ ] `JWT_SECRET` 是至少 32 位的随机值
- [ ] `DATABASE_URL` 是真实 PostgreSQL 连接串
- [ ] `WECHAT_APPID`、`WECHAT_SECRET` 是当前小程序的真实值
- [ ] `QWEN_API_KEY` 是轮换后的服务端 Key
- [ ] 首次管理员账号使用强密码；改密后删除 `ADMIN_BOOTSTRAP_*` 环境变量并重新发布
- [ ] 日志不记录请求头、密码、AppSecret、API Key、健康问卷答案或图片内容
- [ ] `GET /health` 返回 200 且 `env` 为 `production`

静态检查示例：

```powershell
python deploy/cloudbase/validate_config.py deploy/cloudbase/environment.local.json
```

## 六、小程序正式网络

### 使用 `wx.cloud.callContainer`

- [ ] 小程序已关联目标 CloudBase 环境
- [ ] `wx.cloud.init` 使用真实 `envId`
- [ ] 每次调用的 `X-WX-SERVICE` 使用真实 `serviceName`
- [ ] 普通 JSON 请求、multipart 上传、头像 / 聊天图片显示和预览均完成真机回归
- [ ] 确认没有其他客户端需要公网 API 后，再关闭不需要的公网入口
- [ ] 正式包不包含 `localhost`、`127.0.0.1`、局域网 IP、示例域名或未使用旧页面

## 七、隐私、内容和账号能力

- [ ] 微信公众平台“用户隐私保护指引”与代码实际调用的相机、相册、头像、昵称等能力一致
- [ ] 首次收集敏感信息前有明确目的、范围和用户操作
- [ ] 健康评估答案、咨询内容和图片按敏感个人信息保护，限定访问角色和保存期限
- [ ] 用户可以修改昵称、头像，也可以发起账号注销 / 数据删除
- [ ] 注销后令牌失效，业务数据按既定规则删除或依法留存并完成去标识化
- [ ] 评论、点赞、收藏和消息通知的可见范围与权限正确
- [ ] 用户评论、昵称、头像和咨询图片经过微信内容安全检查；服务不可用时生产环境拒绝写入，不静默放行
- [ ] 评论具备举报和后台处理能力，运营方有审核与处置流程
- [ ] 隐私政策、用户协议、客服电话 / 联系方式均为经主体确认的真实信息

## 八、AI 与内容质量

- [ ] Qwen Key 只在后端环境变量中，小程序代码和 Git 历史不含可用 Key
- [ ] AI 请求有用户鉴权、单用户日限额、分钟级频控和失败回滚
- [ ] AI 输出标识为 AI 生成，并包含合理的就医提醒
- [ ] 对急症、用药、诊断和个体化治疗问题采用安全回复或建议线下就医
- [ ] 科普文章由疾控中心提供或审核，管理端记录来源和更新时间
- [ ] 患者不能上传、发布或替换科普素材

## 九、提审前真机验收

- [ ] 患者端：登录、健康评估、历史记录、打卡、点赞 / 评论 / 收藏、消息、个人资料、注销
- [ ] AI：文字咨询、图片分析、次数上限、错误提示和免责声明
- [ ] 在线指导：只在资质覆盖时测试预约、匹配、医患消息和图片；否则确认入口已经关闭
- [ ] 管理端：登录、修改密码、用户 / 医生管理、问卷管理、内容与评论处置
- [ ] 大字号、长昵称、窄屏、弱网、重复点击、登录过期和拒绝隐私授权
- [ ] iOS 与 Android 各至少一台真机，体验版账号与普通用户账号分别验证
- [ ] 后端容器重启后数据库和用户图片仍然可用

## 十、上传、审核和发布顺序

1. 完成后端生产部署和 `/health` 验证。
2. 填入真实 API 配置，运行后端测试、小程序测试、语法检查和敏感信息扫描。
3. 在微信开发者工具上传版本，填写真实版本号和变更说明。
4. 设置体验版，按第九节做完整真机验收。
5. 在公众平台核对名称、简介、图标、类目、资质、隐私指引和用户协议。
6. 提交审核；如审核意见要求调整功能或类目，按实际业务边界修改后重新回归。
7. 审核通过后发布，观察错误率、接口延迟、AI 调用量、数据库连接数和用户反馈。
8. 保留上一稳定版本和数据库备份，准备回滚。

## 十一、当前阻塞项

- [x] 已创建 CloudBase PG 环境并确定 `envId` 与 `serviceName`
- [ ] 当前免费体验环境未提供可用的 PostgreSQL 直连地址、角色和密码；需选择能让云托管安全直连 PG 的正式套餐或独立数据库
- [ ] 尚无生产 PostgreSQL 连接信息
- [ ] 尚未创建并注入仅供后端使用的 CloudBase `service_role` API Key，也未创建私有 `user-media` Bucket
- [ ] 泄漏过的百炼 Key 仍需由账号管理员撤销并轮换
- [ ] 真人在线指导功能与当前小程序主体、服务类目及医疗资质尚待核验
- [ ] 微信开发者工具服务端口需由用户在安全设置中开启，才能使用 CLI 上传

这些值和操作涉及账号权限、计费、密钥或对外提交，不能由仓库中的占位符代替。完成后应先上传体验版；提交审核和正式发布属于对外操作，应在最终页面再次核对版本与材料。
