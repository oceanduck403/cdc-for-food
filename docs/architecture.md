# 系统架构

## 总览

```
┌────────────┐     HTTPS/JSON     ┌──────────────────┐
│ 微信小程序 │ ─────────────────▶ │  FastAPI 后端     │
│ (原生)     │ ◀───────────────── │  (Python 3.11)    │
└────────────┘                    └──────────────────┘
                                          │
                                          ▼
                          ┌───────────────────────────┐
                          │ PostgreSQL  | Redis | OSS  │
                          └───────────────────────────┘
                                          │
                                          ▼
                          ┌───────────────────────────┐
                          │ 商用菜品识别 API          │
                          │ (百度/阿里/自建，通过抽象) │
                          └───────────────────────────┘
```

## 模块职责

- **小程序前端**：原生微信小程序，提供登录、拍照、报告、知识库、GIS、用户中心六大业务域
- **FastAPI 后端**：JWT 鉴权、用户档案、膳食分析、知识库、GIS 数据、视觉识别中转、成本闸口
- **PostgreSQL**：用户档案、膳食历史、知识库文章、GIS 风险点
- **Redis**：每日分析次数限流、识别结果缓存
- **OSS**：膳食图片持久化（避免污染业务库）
- **第三方视觉 API**：通过 `vision_service` 抽象调用

## 关键数据流

1. **拍照识膳食**

   ```
   用户拍照 → 小程序压缩 → POST /meals/analyze (base64)
     → 限流校验（Redis） → 调用视觉 API
     → 营养素换算（nutrition_service） → 写入 PostgreSQL
     → 生成个性化建议 → 返回报告
   ```

2. **知识库检索**

   ```
   小程序 GET /knowledge?category=guide&q=xxx
     → 数据库查询 → 返回富文本 + 元数据 → 小程序渲染
   ```

3. **毒蘑菇 GIS**

   ```
   小程序 GET /gis/mushroom-risk?city=chengdu
     → 返回 marker 列表 → 地图组件渲染
     → 用户点击 → GET /gis/mushroom-risk/{id} → 详情浮层
   ```

## 决策记录

| 决策 | 依据 | 备选 | 风险 |
| --- | --- | --- | --- |
| 原生小程序 | 微信生态兼容最好、审核稳定 | Taro、uni-app | 未来多端需要重写 |
| FastAPI | 与未来营养/AI 服务同语言、类型校验完善 | Django、Spring | 团队需要熟悉 asyncio |
| 商用识别 API | 节省自建成本、可快速上线 | 自训练 | 长期成本与可控性 |
| 独立云服务器 | 便于等保与合规控制 | 云开发 | 运维成本略增 |
