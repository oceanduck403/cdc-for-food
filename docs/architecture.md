# 系统架构

> 当前正式方案以 CloudBase 云托管、PostgreSQL、私有 COS 和服务端 Qwen 网关为核心。

## 总览

```
┌────────────┐     HTTPS/JSON     ┌──────────────────┐
│ 微信小程序 │ ─────────────────▶ │  FastAPI 后端     │
│ (原生)     │ ◀───────────────── │  (Python 3.11)    │
└────────────┘                    └──────────────────┘
                                          │
                                          ▼
                          ┌───────────────────────────┐
                          │ PostgreSQL  | 私有 COS     │
                          └───────────────────────────┘
                                          │
                                          ▼
                          ┌───────────────────────────┐
                          │ 阿里云百炼通义千问         │
                          │ (文本与食物图片分析)       │
                          └───────────────────────────┘
```

## 模块职责

- **小程序前端**：原生微信小程序，提供健康评估、健康打卡、AI 咨询、科普互动、个人中心和按资质开放的医生指导
- **FastAPI 后端**：微信登录、JWT 鉴权、角色权限、用户档案、AI 网关、互动内容与成本闸口
- **PostgreSQL**：用户、评估、打卡、膳食报告、互动、咨询和 AI 用量记录
- **私有 COS**：持久保存头像和咨询图片；数据库仅保存不透明引用，客户端通过短期签名代理读取
- **Qwen**：由后端持有密钥并调用，原始食物照片不写入业务数据库

## 关键数据流

1. **拍照识膳食**

   ```
   用户拍照 → 小程序压缩 → POST /ai/food-analysis (base64)
     → PostgreSQL 用量预占 → 服务端调用 Qwen
     → 校验结构化结果 → 写入 PostgreSQL
     → 生成个性化建议 → 返回报告
   ```

2. **知识库检索**

   ```
   小程序 GET /knowledge?category=guide&q=xxx
     → 数据库查询 → 返回富文本 + 元数据 → 小程序渲染
   ```

3. **毒蘑菇 GIS**

   ```
   小程序 GET /gis/mushroom-risk?city=chengdu
     → 返回 marker 列表 → 地图组件渲染
     → 用户点击 → GET /gis/mushroom-risk/{id} → 详情浮层
   ```

## 决策记录

| 决策 | 依据 | 备选 | 风险 |
| --- | --- | --- | --- |
| 原生小程序 | 微信生态兼容最好、审核稳定 | Taro、uni-app | 未来多端需要重写 |
| FastAPI | 与未来营养/AI 服务同语言、类型校验完善 | Django、Spring | 团队需要熟悉 asyncio |
| 服务端 AI 网关 | 密钥不进入小程序，并统一限额和安全提示 | 小程序直连 | 第三方服务可用性与调用成本 |
| CloudBase 云托管 | 可运行现有 FastAPI 容器并接入微信生态 | 自建云服务器 | 需配置云资源、数据库与费用告警 |
