# 问卷加载修复与就诊登记表

登记表来源为 `0-体重管理门诊就诊信息登记表5.9.docx`，保留原表全部 10 个字段和顺序：就诊日期、登记号、姓名、性别、年龄、联系电话、就诊诉求、复诊日期、接诊医生、备注。

新增模板类型为 `weight_visit_registration`，名称为“体重管理门诊就诊信息登记表”，排序为 0。前 6 项为第一页，其余 4 项为第二页。日期使用日期选择器，可以清空；电话兼容固定电话；未填项目在提交前统一提示，允许确认后提交。登记表不提供 AI 健康评分。

后端启动时建立缺失的数据表，并仅在登记模板不存在时新增。也可通过原有初始化脚本建立模板。已有模板（包括停用和管理员编辑过的登记模板）、旧基本信息表和历史答案不被覆盖。

## 本次修复

- 问卷卡片使用原生 navigator，列表加载时生成包含 templateId 的完整地址，避免缺少 dataset 属性造成 undefined / NaN 请求。
- 题目兼容数组和 JSON 字符串，步骤统一为从 0 开始的连续分页，缺省步骤进入第一页。
- 在 JavaScript 中生成当前页题目和选项选中状态，移除 WXML 中的方法调用及循环条件混用。
- 加载失败显示错误和重试入口，隐藏翻页与提交按钮，避免空白问卷仍能提交。
- 问卷提交、管理员模板增删改及提交记录筛选使用正确的请求参数格式。
- 历史记录显示模板名称，可以逐页查看，禁止修改；保留本地旧问卷记录读取。
- 修复管理员提交列表中未 await 的结果访问错误，登记内容可在后台查询。

## 验证

在仓库根目录运行 `node --test miniprogram/tests/survey.test.js`。
在 server 目录运行 `.venv\Scripts\python.exe -m pytest tests -q`。
使用微信开发者工具自带 wcc / wcsc 编译调查列表与问卷详情模板、样式。

微信开发者工具重新编译后，在“调查评估”进入“体重管理门诊就诊信息登记表”；填写两页并提交，需有效患者登录状态。登录失效或网络失败时不显示保存成功，当前答案仍保留在页面中。重启后端会补充缺失的登记模板，无需清空数据库。

## 同一 Wi-Fi 手机测试

接口地址已统一读取 `miniprogram/utils/config.js` 的 `apiBase`，当前为 `http://192.168.0.102:8000/api/v1`。电脑 IP 改变后需同步修改并重新编译。App 恢复时调用的每日次数刷新方法已补齐，未登录或接口失败不会抛出生命周期异常。

1. 保持电脑后端运行并与手机连接同一个 Wi-Fi。
2. 手机浏览器打开 `http://192.168.0.102:8000/health`，应显示包含 `status: ok` 的 JSON。电脑能访问不代表手机一定能访问；打不开时检查网络隔离和电脑入站防火墙规则。
3. 微信开发者工具点击顶部“真机调试”，使用项目开发者微信扫码。iOS 如提示访问本地网络，需要允许。
4. 进入调查评估，打开第一张“体重管理门诊就诊信息登记表”，测试填写、下一步、上一步和答案保留。真实提交需要有效登录。

正式上线需先将后端部署到公网 HTTPS 地址，配置小程序服务器合法域名，将 apiBase 改为该地址后重新编译上传。上传后可设置体验版并添加体验成员；面向公众发布还需提交审核和发布。仅上传前端不能让手机访问电脑上的 localhost。当前没有执行上传、审核或发布。
